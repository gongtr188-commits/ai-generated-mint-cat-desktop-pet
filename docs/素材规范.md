# 素材规范

> 给"下一批素材"看的文档。生成新素材前读一遍，能省掉一轮返工。
> 所有规格由 `tools/build_assets.py` 强制执行，改规格改那里。

## 1. 画布与归一化

| 项 | 值 | 说明 |
|---|---|---|
| 画布 | **896 × 768**（横向） | 所有素材统一。v0.7 前是 768×768，加宽是因为坐姿/趴姿在同一机位下比站姿宽得多 |
| 内容高 `CHAR_H` | 660 | 管线自动把内容**高度**归一到这个值（宽度封顶时除外，见下） |
| 内容宽上限 `CONTENT_MAX_W` | 848 | 两侧各留 24px。**归一是双约束**：`min(身高归一, 848/(半宽+最大横移))` |
| 基线 `BASELINE` | 24 | 内容底边距画布底 |
| 水平 | 居中 | 按内容 bbox 居中，不是按源图画布居中 |

**新素材的宽度预算**：归一后内容宽 = `660 × 源内容宽 / 源内容高`，必须 ≤ 848。
实测现有静姿图里最宽的是 `坐下_正面` 830。也就是说**坐/站这一类还能再宽 18px**。

**横躺的身体一定会撞这个上限**，而且这是对的：`向左/向右趴着睡觉` 按身高归一需要
995~1094px 宽（源内容宽高比 ≈ 1.5），封顶之后实际缩放 1.20 而不是 1.43/1.55，
内容高只剩 513~554（`CHAR_H` 的 78~84%）。**躺着的身体本来就比站着矮**，
这不是基准漂移；以前没有封顶时两头（头和尾巴）会被画布直接切掉。
所以：做横躺类素材时**不必**为了"归一后不缩水"去把角色画小，
但**必须**保证头和尾巴离画面边缘有余量（管线会按 `src_clipped` 报贴边）。

**归一化按高度为主、宽度封顶。** 依据：转身视频整段共用同一缩放，是"同一角色
不同朝向"的真值，视频里背面 = 与正面同高、窄 12.6%。高度归一后静帧复现了同一比例。

## 2. 源图要求

- **背景要浅、要均匀**。管线判背景用的是"**离本帧背景色多近**"（`FLOOD_TOL=8`，
  本帧背景色 = 四边 6px 环的中位），所以背景和她白毛(≈248)只差几级**不再致命**——
  白毛被暗描边围住，泛洪走不到它。
  历史包袱：旧判据是绝对阈值 `min(通道)>235`，于是 h264 在描边旁把背景压暗到 237 的那一圈
  会漏网，她耳侧蝴蝶结外就糊一圈白色锯齿毛刺（开发文档 §11.12–§11.13）。已修。
- **渐变暗角与地面投影：v0.14 起能自动吃掉，但仍然要避免。** 这两样都不是纯背景色，
  离四边中位差 10~30 级，卡在 `FLOOD_TOL=8` 外就**整片留在前景里**：
  `向右趴着睡觉` 的暗角让前景虚胖到 44 万 px（真身 20 万，包围盒 y12~708 而不是 129~555）；
  `微笑拥抱` 身下的投影在深色桌面上是一摊白雾，而且逐帧忽大忽小 —— 用户报的
  "抱还没扣干净、有抖动"有一半就是它。现在多一档判据 `BG_GRAY_TOL=30` + `BG_GRAY_SPAN=16`
  （**低饱和**的浅灰才放宽，通道极差仍要小），前提不变：只能从四边连通。
  实测放宽后其余 15 段素材面积变化 <1.5%，拥抱只掉 9k px（就是那摊投影）。
  **为什么仍然要避免**：判据认的是"颜色像背景 + 与背景连通"，
  所以任何**贴着她身体、又不连通到四边**的浅灰（比如脚底阴影被腿围住）照样会留在身上，
  而带极差的彩色投影（暖光、冷光）两档都认不出来。
  - 合格线：四边中位亮度稳定、通道极差 <12、**画面四边不要有暗角或渐变**、**身下不要画投影**
  - 更好：**带 alpha 通道**（管线可直接用真透明，省掉整层猜测）
- **角色不许碰到画面边缘**（这条现在是硬要求）。素材规范原本就写"四周留白 ≥100px"，
  但 `向左走_四足` 没做到——她从画面右侧一路走到左缘出画，成品里脸被切掉一半。
  管线现在会量 `src_clipped`（贴边 **且** 该帧前景比整段中位少 8%）并报出来。
- **位移动作请保持角色在画面里居中**：走/跑/爬这类素材，管线要区分
  "她迈步造成的身体摆动"（要保留）和"整个机位推着她走"（要抵消）。
  实测：`向右跑` 漂移 17px 全是摆动 ✅；`向左走_四足` 55px 是纯平移 ❌。
- **走路/跑步素材最好凑成整数个步态周期**：素材长度不是整数周期时，循环播放
  每圈都会相位错位（实测 `向右走_四足` 接缝是相邻帧差的 11 倍）。
  管线现在会自动截到整数周期，但**能一次给对更好**。
- 角色**不要贴画布边缘**，四周留白（实测留白 100~250 px 都可以，管线会裁）
- **水印**：管线会按颜色签名定向清除，但前提是它落在画面右下角那条带子里
  （`build_assets.WM_BOX`，比例坐标）。换生成器/换水印位置就要重标这个框。
  压在她毛发上的那部分水印会和毛混色、清不掉（只能留淡痕，硬清会在身上打穿白洞），
  所以**能选无水印导出就选无水印**
- **视频要压住压缩噪声**。h264 会在高对比的暗描边外圈甩出一圈振铃亮斑，合成到深色
  桌面上就是一圈白边。管线靠"轮廓内收 2px"补救，但源图干净得多就不用补
  （实测视频帧亮边占前景 0.91~0.95%，静帧只有 0.09%）。能出 **PNG 序列帧或低压缩
  H.264/HEVC 高码率**就别用默认码率
- 同一批素材尽量同一来源/同一提示词，色调差异大时管线会向正面基准靠拢，但强度只有 0.5

## 3. 命名与放置

```
素材/薄荷_猫猫/
├─ 图片/  薄荷猫猫_正面 / _左面 / _右面 / _背面
│         薄荷猫猫_坐下_正面 / _趴下_正面 / _向左趴着 / _向右趴着
└─ 视频/  薄荷猫猫_转身360度 / _静立_正面 / _向左走 / _向右走
          薄荷猫猫_向左跑 / _向右跑
          薄荷猫猫_坐下 / _趴着转180度 / _向左走_四足 / _向右走_四足
          薄荷猫猫_正面趴着 / _微笑拥抱 / _打瞌睡 / _向左趴着睡觉 / _向右趴着睡觉
```

`build_assets.py` 里的两张映射表决定文件名 → 语义键。**键是完整文件名**（不含扩展名）：

```python
POSE_MAP  = {"薄荷猫猫_正面": "front", "薄荷猫猫_坐下_正面": "sit_front", ...}
VIDEO_MAP = {"薄荷猫猫_转身360度": "turn", "薄荷猫猫_坐下": "sitdown", ...}
```

> **为什么不用后缀**：曾经写成 `{"正面": "front"}` + `glob("*正面.png")`。
> 加了 `坐下_正面`、`趴下_正面` 之后 `_正面` 结尾的有三个，
> `front` 静默取到了坐姿图（内容宽 706→830、站立转身 keys 全部漂移），且不报任何错。
> 现在 `pick_asset()` 精确匹配，缺文件直接退出并列出相近文件名。

**加新素材 = 在这里加一行完整文件名 + 把文件放进对应目录 + 重跑管线。** 主程序零改动。

### 朝向语义

`side_left` = 脸朝画面左 = **向左走时用**。命名和用途同向，不要生成"身体朝左但脸朝右"的图。

### 驻留姿态：一个姿态可能要求"每个朝向一段微动"

姿态注册表里的 `idle` 可以是**与 `faces` 等长的列表**（`build_assets.POSTURES`），
运行时按当前朝向取那一段来来回播；`None` 表示该朝向没有微动、停在静姿图上。
现有两例：

```python
"prone":    faces=[prone_front, prone_left,  prone_right]
            idle =["prone_idle",   None,       None      ]   # 只有正面那段会动
"sleeping": faces=[sleep_left,    sleep_right]
            idle =["sleep_left",   sleep_right]              # 左右躺各一段
```

**加这类素材时的三条硬要求**：

1. **列表长度必须等于朝向数**，`check_registry()` 开跑前就会核对并退出。
   配错的代价不是报错，而是"切到那一侧时她突然不动了"（查不到素材就退回静帧）。
2. **每个朝向都要有一张静姿图**（`POSE_FROM_VIDEO` 可以从对应素材第 0 帧复制，
   别另出一张 —— 另出的图和动画对不齐，进入的那一 tick 会跳一下）。
3. **同一姿态的几段素材必须是同一副身体**：`向左趴着睡觉` 与 `向右趴着睡觉` 是镜像的
   同一种侧躺，所以能当一个姿态的两个朝向；而 `正面趴着`（趴坐呼吸）与它们不是同一副
   身体，所以是另一个姿态。这条判断错过两次，代价见开发文档 §13.16⑥ 与 §13.17①。

侧躺睡没有"正面那张脸"，所以它整个姿态受「左右趴着」开关管：
关掉时菜单里不摆这一项、`start()` 再挡一道、在飞的当场起身、排队的意图作废。
**四道都要**，只做一道都会漏（§13.17③）。

### 动画命名建议（将来加动作时）

| 语义键 | 内容 | 备注 |
|---|---|---|
| `turn` | 原地 360° 转身 | 已有，121 帧 |
| `walk_left` / `walk_right` | 向左 / 向右走一个完整步态周期 | 已有；需要首尾同帧，便于循环 |
| `run_left` / `run_right` | 向左 / 向右跑 | 已有。跑=同一趟行程的**快步态**，运行时按行程远近自动选 |
| `sit` | 坐下→坐定 | 坐定那帧另存为静态姿势 `sit` |
| `hop` / `stretch` / `groom` | 小跳 / 伸懒腰 / 舔毛 | 首尾回正面，便于接回 idle |
| `walk_toward` / `walk_away` | 面向镜头走来 / 背对镜头走去 | **可选增强**，见下方说明 |

**循环类动画（走/跑/爬）的两个硬要求**，都已经被管线自动检查并写进清单：
1. **首尾能接上**（接缝 ≈ 相邻帧差，不要出现 11× 这种）；素材长度最好是整数个步态周期。
2. **角色不贴源画面边缘**（贴边且前景面积掉 8% 以上会被报成 `src_clipped`）。

不满足的现成反例就是 `向左走_四足`：她从画面右侧一路走出左缘，脸被切掉，
而且整段没有可重复的步态周期 —— 既不能截前缀也不能循环，只能重做。
新素材到货先跑 `py -3 tools/source_check.py`，30 秒出结论。

动画帧数不要求统一。**不要按帧数折算播放速度**，各按原始帧速播。

### 纵向步态：现在不是欠账，是可选增强

漫游改成**斜着走**之后（横向播侧视步态、纵向按比例带位移，见开发文档 §12.3），
她在屏幕上已经能走到任意位置，不再需要"上下走"的画法。

斜着走的代价是**斜率有上限**（`WALK_SLOPE=0.45`）：目标点太靠近正上/正下方时，
纵向位移会被夹掉，她到不了那个点，得靠几趟斜着走绕过去。

补这两段视频能把这个限制去掉，让她可以朝任意方向直走：

| 项 | 要求 |
|---|---|
| 视角 | `walk_toward` 正对镜头；`walk_away` 完全背对镜头（就是背面图那个角度） |
| 动作 | **原地走**，不要真的走出画面，和现有向左走 / 向右走一样 |
| 周期 | 24 帧一个完整步态周期（与现有两段走路对齐，方便共用相位判据） |
| 时长 | 约 5 秒 / 121 帧 / 24fps，与现有素材一致 |
| 背景 | 纯白底，右下角允许有水印（管线会清） |
| 落地 | 脚底位置保持在同一条水平线上，便于基线归一 |

优先级不高，属于锦上添花。

### 步态类视频请让**每个周期长得一样**

只有周期一致，管线才能截出一段"播完再接头看不出来"的循环。判据是量出来的：
把循环截成 k 个周期后，"末帧→首帧"的画面差与段内相邻帧差之比必须 ≤2.5。

| 素材 | 整段接缝 | 截到整数周期后 | 结论 |
|---|---|---|---|
| 向左走 / 向右走 / 向左跑 / 向右跑 | 0.25~1.53× | 不必截，本来就能接 | 好 |
| `向右走_四足` | 11.13× | 4 个周期 9.49×、3 个 7.72×、**2 个才 2.05×** | 只能退到 2 周期循环，代价是爬行时重复同两步 |
| `向左走_四足` | 28.79× | 量不出周期 | 废素材（见下） |

`向右走_四足` 这条说明生成器**每圈的脚位并不重合**：整段里第 1 圈和第 4 圈差到 9.5 倍相邻帧差，
于是"多留几圈"反而更接不上。要修就得让同一素材的每一圈姿态一致（或者干脆只给一圈）。

`向左走 / 向右走` 都是 24 帧一个步态周期。生成瑕疵往往**按周期重复出现**，
所以排查时先按 `i % 周期` 分组看指标，比逐帧找快得多。
向右走的"多手"就是这么定位的，但**第一次只定位到相位 22/23/0/1 是错的**——
按同一指标把 8 个循环全量出来后，真实范围是 **ph19→ph2、峰值在 ph21**
（教训见开发文档 §11.11：门限不能拿被筛过的那批数据自己定）。

### 每个动画要声明放置策略（`build_assets.ANIM_MODE`）

| 策略 | 适用 | 原因 |
|---|---|---|
| `per_frame` | 原地转身 | 身高本就不该变，素材里 7.3% 起伏是噪声，逐帧归一压掉 |
| `sequence` | 静立呼吸、走路步态、坐下、趴着转180、打瞌睡，任何"原地不动但有微动"的 | 高度起伏**就是**呼吸、横向位移**就是**摇摆，压掉动画就白做 |
| `recenter` | 四足走、正面趴着的趴坐微动、左右躺睡 | 素材里人**真的在画面内平移**（向左走_四足实测漂移 69px，现有走路只有 4~6px，躺睡 8px 躺在地上还左右挪）。sequence 会把它保留成"摇摆"，看起来是爬着滑来滑去；所以逐帧水平居中抵消漂移，但**共用整段缩放**保留爬行的高度起伏 |
| `head` | 微笑拥抱这类"手大幅动、身体不动"的 | 包围盒中心被手臂开合带偏 7px，而**头部只动 1.1px**。sequence 按包围盒给锚点 = 让整只猫跟着手左右晃（实测抖动 0.78 屏幕 px／翻转率 0.61）。锚住头部之后 0.10px／翻转 0.81，手照样抱 |

新加动画时先判断它的尺寸变化是噪声还是信号，再选策略。选错的代价是动画看起来是死的。
判据：量一下**水平中心在整段里的漂移幅度**。个位数像素 → 是摇摆，用 `sequence`；
几十像素 → 是素材自己在平移，用 `recenter`。
如果漂移只来自**四肢开合**（躯干与头不动），用 `head` —— 判据是分别量"包围盒中心"和
"上半身（顶部 35% 带）中心"的移动量，两者差几倍就是选错了锚点。

**位移类动画还会自动做纵向去抖**（`BOB_ANIMS` = 走/跑/四足走六段）：让**头部带质心**
沿 5 帧低频趋势走，削掉逐帧乱跳、保留每步一次的真弹跳（5 帧 ≪ 步态周期 14~26 帧）。
实测向右跑相邻显示帧的头跳 3.41→1.37 屏幕px。
做这类素材时真正该避免的是**同一周期内身体忽高忽低**：管线只能削高频，
如果每步的弹跳本身比另一侧大一倍（现在 `向右跑` 就是 `向左跑` 的 1.3 倍），
压平它就会变成贴地滑行，只能重出。坐着/睡着/呼吸这几段**不做**纵向去抖 ——
底边对齐就是脚踩在地上，钉住头会让脚离地。

`sequence` 模式的水平摆位用的是**相对偏移量**（该帧中心 − 全段中位中心），
不是绝对坐标 —— 绝对坐标会让整段动画相对静帧平移，交接时跳一下，
严重时顶到画布边缘把肢体切掉。加新动画后跑一次
`py -3 tools/smoke_test.py`，里面的对齐/截断锁会直接报出来。

### 同一角色的所有素材必须是"同一张身体"

管线能把尺寸归一、能把相位对齐，**但没法把画得不一样的身体画成同一个**。
`py tools/seam_check.py` 用一把尺量出每一处"画面来源换人"的接缝，刻度是：

| 值 | 含义 |
|---|---|
| 0.55 | 相邻两帧的自然差，完全看不出来 |
| 4.04 | `正面.png ↔ 静立视频第 0 帧` —— 产品里已存在、用户没抱怨过，当"可接受"基线 |
| 19~31 | 一次真正的姿态变化（站↔趴 19.1、站↔坐 27.7、转 90° 30.8），肯定看得出来 |

**当前超标的四类，全部落在素材上，改代码无效**（数字为 48×48 灰度平均差）：

| 素材对 | 实测 | 证据 |
|---|---|---|
| `坐下.mp4` 站立段 ↔ `正面.png` | 11.8 | 同一时刻她宽 44px、高 10px。整段重缩放最好也只降到 8.6，说明差的是**形状**不是尺寸 |
| `向右跑.mp4` ↔ `右面.png` | 11.2~13.8 | 宽高比 0.992 vs 0.942（尾巴/身子画得更蓬）。**同一段素材的镜像兄弟 `向左跑 ↔ 左面` 只差 2.0** —— 左右不一致 |
| `向左走_四足 / 向右走_四足` ↔ 趴姿静帧 | 14.3~25.1 | 起步只有 2.6，说明静帧本身对得上；是爬行时身体起伏太大，停在哪一帧不可控 |
| 站 ↔ 趴 | 19.1 | **没有趴下/起身过渡视频**，爬走结束只能硬切 |

所以补素材时请优先：① 趴下／起身两段过渡视频；② 重出 `向右跑`（与 `向左跑` 同比例同画法）；
③ 重做 `坐下.mp4` 开头那几帧站立（对齐 `正面.png`）。
交付前自检：`py tools/seam_check.py`，看有没有新的行落到"略跳"以上。

## 4. 双形象 / 多皮肤

目录从一开始就按皮肤分：`assets/skins/<skin_id>/{poses,anim,sounds}/`。

- **换整套形象**（比如睡衣版）→ 新增 `skins/pajama/`
- **同一形象的可拆卸部件**（比如头顶小黑猫发夹拿掉）→ 用 `variants`：

```json
"variants": {
  "no_clip": {
    "poses": { "front": "skins/default/poses/front_no_clip.png",
               "back":  "skins/default/poses/back_no_clip.png" }
  }
}
```

**兜底规则（已写进代码，别绕过）**：变体缺某个姿势 → 回退基准同名 → 再缺 → 一律回退
`front`。所以做双形象时**哪怕只给了部分变体素材，也不会出现"该没发夹的地方冒出个发夹"**。

命名约定：基准无后缀，变体加 `_<variant>` 后缀（`front_no_clip.png`）。

## 5. 声音

`assets/skins/<skin_id>/sounds/*.mp3`，清单里预留了目录但 v0.1 未接。

## 6. 交付前自检

```bash
py -3 tools/source_check.py         # 新素材到货第一步：漂移/周期/接缝/贴边裁切
py -3 tools/build_assets.py         # 重跑管线，看报告表
py -3 tools/inspect_assets.py       # 出对比图到 docs/preview/
py -3 tools/strip_check.py          # 每段动画一张逐帧深色胶片
py -3 tools/seam_check.py           # 状态切换处的接缝（基线 4.04，>8 就该提素材需求）
py -3 tools/jitter_check.py         # 抖动：方向翻转率 × 屏幕像素摆幅
```

看四样东西：

1. 报告表里每张图 `scale` 是否合理、`tone` 与基准的差距
2. `poses_halo.png`（品红底）—— 有没有白边、残留点、水印没清干净
3. `poses_row.png` / `poses_overlay.png` —— 新素材和已有素材并排、叠起来是否协调
4. `seam_check.py` 与 `jitter_check.py` 有没有新行落到"看得见"以上 ——
   这两张表量的都是**素材之间画得不一致**，代码改不动，只能重出。
   ⚠ 读 `jitter_check` 的数之前先记住它是**运行时口径**：按 `stride` 抽稀之后的
   显示序列、量**头部最大单帧跳**，不是逐帧平均。逐帧平均会把一记 3px 的尖峰
   摊成 0.05px，从而"全绿但用户说抖"（开发文档 §13.18④ 就是这一条）

**不要**在实机上看之前就先手动改素材尺寸；管线归一化能解决的，别在源图上动手。

## 7. 转身 / 旋转类视频的特殊要求

管线会从成品帧自动反算三样东西并写进 `manifest.anims.turn`：
`cycle`（真正转完一圈的帧数）、`keys`（四朝向对应的帧号）、`path`（累计视觉进度）。

生成这类视频时注意：

- **转完就停，别多留静止尾巴。** 当前这段 121 帧里第 98 帧就转完了，后面 23 帧是
  原地不动的正面——管线会自动把 `cycle` 截到 98 把它们排除，但**素材白生成了一截**。
  要求视频长度 ≈ 实际旋转长度。
- **尽量匀速。** 实测四个 90° 分别占 27/18/23/30 帧，最不均匀的那段会让转身
  在某一个方向上明显比别的方向"卖力"。采样已按视觉进度等分来补偿，但源头匀一点更好。
- **首帧必须是正脸**，管线以第 0 帧为周期起点做检测。
- **原地转身的每一帧身高应当一致。** 管线现在逐帧把内容高钉死到 `CHAR_H`
  （v0.2.2 起；之前"整段共用一个缩放"是错的，实测素材自身有 7.3% 的高低起伏，
  不逐帧压平就是"颠簸"，而且收尾会从 ~620 弹到 660）。
  生成时如果角色明显忽大忽小，管线会把它拉平，但**源头稳一点画质更稳**。
- 转身**不要边转边推镜头**（缩放变化会被逐帧归一误当成身高变化）。
